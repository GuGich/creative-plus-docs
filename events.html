События

События запускают выполнение последовательности. Каталог включает события игроков, мира и сущностей.

Ниже — справочные записи, извлечённые из технического каталога Creative+. Используй фильтр, чтобы найти нужный идентификатор. Описание передаёт поведение из исходного руководства; названия и расположение блоков в интерфейсе могут отличаться.

PLAYER_JOINСПРАВОЧНАЯ ЗАПИСЬ

event | category: PLAYER_WORLD | default target: the player who joined | cancellable: no

Fires when a player enters play mode in this world: the player joins the world while it is in play mode, the world is switched to play mode (it fires for every player who is not coding), the player comes back from the code area with /play, or the player types /play again while playing.

notes:

  • When the world is switched to play mode, the code restarts first, then PLAYER_JOIN runs for each player, then PLOT_WORLD_STARTS runs once.
  • /play while already playing gives PLAYER_REJOIN, then PLAYER_QUIT, then PLAYER_JOIN. A coder who types /play gets only PLAYER_JOIN (the code is restarted first).
  • This is the best place to start loops and create bossbars and scoreboards (see the guide, section 5.7).
PLAYER_QUITСПРАВОЧНАЯ ЗАПИСЬ

event | category: PLAYER_WORLD | default target: the player who leaves | cancellable: no

Fires when a player in play mode stops playing in this world: the player leaves the world or the server, goes to the code area with /dev, the world is switched to build mode, or the player types /play again.

notes:

  • The player is still in the world when the line runs, so you can still read the player's values and send messages.
  • Do not use GAME_WAIT here: after the wait the player is usually gone and the rest of the line does nothing.
PLAYER_REJOINСПРАВОЧНАЯ ЗАПИСЬ

event | category: PLAYER_WORLD | default target: the player who typed /play | cancellable: no

Fires when a player who is already playing types /play (restart for this player). Right after it come PLAYER_QUIT and PLAYER_JOIN for the same player.

notes:

  • Does not fire for a player who types /play from the code area.
PLAYER_BLOCK_INTERACTСПРАВОЧНАЯ ЗАПИСЬ

event | category: PLAYER_WORLD | default target: the player | cancellable: yes

Fires on every interaction of the player's main hand: left or right click on a block or in the air, and physical actions (stepping on a pressure plate, trampling farmland).

event values: EVENT_ITEM (ITEM): the item in the hand (air if empty); EVENT_BLOCK (ITEM): the clicked block as an item (nothing for air clicks); EVENT_BLOCK_LOCATION (LOCATION): center of the clicked block; EVENT_INTERACT_ACTION (TEXT): LEFT_CLICK_BLOCK, RIGHT_CLICK_BLOCK, LEFT_CLICK_AIR, RIGHT_CLICK_AIR or PHYSICAL; EVENT_BLOCK_FACE (TEXT): clicked side of the block (UP, DOWN, NORTH, SOUTH, EAST, WEST, SELF)

notes:

  • Off-hand interactions are ignored, so a click fires once. The hand is read with the condition IF_PLAYER_EQUIPMENT_SLOT_EQUALS; here it is always the main hand (no hand for PHYSICAL).
  • Very fast clicks are not all passed to code.
  • The same click also fires PLAYER_RIGHT_CLICK or PLAYER_LEFT_CLICK (this event runs first).
  • Fires often (every click, every step on a plate). Keep the line short.
PLAYER_RIGHT_CLICKСПРАВОЧНАЯ ЗАПИСЬ

event | category: PLAYER_WORLD | default target: the player | cancellable: yes

Fires when the player right-clicks a block or the air with the main hand (RIGHT_CLICK_BLOCK or RIGHT_CLICK_AIR).

event values: EVENT_ITEM (ITEM): the item in the hand (air if empty); EVENT_BLOCK (ITEM): the clicked block as an item (nothing for air clicks); EVENT_BLOCK_LOCATION (LOCATION): center of the clicked block

notes:

  • The Minecraft client sends a right click into the air only when the player holds an item.
  • Holding the right button down can fire it several times.

Fires when the player clicks a slot in an open inventory window, also number-key swaps, drops with Q and clicks on the crafting result.

PLAYER_TAKE_DAMAGEСПРАВОЧНАЯ ЗАПИСЬ

event | category: PLAYER_DAMAGE | default target: the damaged player | cancellable: yes

Fires when the player takes damage from any source (mob, player, fall, fire, lava, void and so on).

event values: EVENT_DAMAGE (NUMBER): damage before armor and effects; EVENT_FINAL_DAMAGE (NUMBER): damage after armor and effects (1 = half a heart); EVENT_DAMAGE_REASON (TEXT): damage cause, for example ENTITY_ATTACK, PROJECTILE, FALL, FIRE, FIRE_TICK, LAVA, DROWNING, VOID, ENTITY_EXPLOSION, BLOCK_EXPLOSION, MAGIC, POISON, WITHER, STARVATION, SUFFOCATION, CONTACT, CUSTOM

notes:

  • Damager ("target":"DAMAGER", %damager%) = the entity that hit, when the damage came from an entity (for arrows it is the arrow). Shooter and projectile are set for projectiles. Victim (both kinds) = the player.
  • Fires also when another server rule already cancelled the damage.
  • For fall damage, PLAYER_TAKE_FALL_DAMAGE fires right after this event.
  • To change the damage use GAME_SET_DAMAGE_OF_EVENT.

PLAYER_DEATHСПРАВОЧНАЯ ЗАПИСЬ

event | category: PLAYER_DAMAGE | default target: the player who died | cancellable: no

Fires 5 ticks after a player died in play mode. At that moment the player is already alive again at the world spawn, and the items were dropped at the death place (unless the code saves the inventory).

event values: EVENT_DAMAGE_REASON (TEXT): the last damage cause of the player

notes:

  • CURRENT_LOCATION here is the spawn, not the place of death. Store the position in PLAYER_TAKE_DAMAGE if you need it.
  • No killer is set here. Use PLAYER_KILL_PLAYER or ENTITY_KILL_PLAYER, they fire right after this event.
  • Does not fire for a spectator or a player with max health below 0.5.
